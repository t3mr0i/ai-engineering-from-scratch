# Git & Collaboration — reusable artifact

Use this card to apply the lesson outcome outside the walkthrough. Its primary goal is to configure git identity and use the daily workflow of add, commit, and push.

## Decision template

- **Situation:** Name the concrete context in which you need to configure git identity and use the daily workflow of add, commit, and push.
- **Options:** Compare at least two approaches while you create and merge branches for isolated experiments without breaking main.
- **Failure probe:** Add a counterexample that tests whether you can write a `.gitignore` that excludes model checkpoints and large binary files.
- **Acceptance evidence:** Define an observable check that demonstrates you can navigate the commit history with `git log` to understand project evolution.

## Reuse checklist

- State assumptions before making the decision.
- Preserve the rejected alternative and the evidence that ruled it out.
- Revisit the decision when an assumption or acceptance threshold changes.
